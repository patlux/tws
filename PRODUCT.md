# Product

## Register

product

## Users

Keyboard-first developers who organize active tmux sessions, worktrees, notes, and coding-agent processes from a terminal. They use tws during focused development work and need to understand workspace state and switch contexts quickly without leaving the keyboard.

## Product Purpose

tws adds a persistent hierarchy and clear operational state to otherwise flat, ephemeral tmux sessions. Success means users can find, launch, inspect, and switch between workstreams with minimal interruption and can trust that displayed session and agent state is current.

## Brand Personality

Focused, fast, understated. The interface should feel dependable and calm under frequent use, with concise language and restrained emphasis.

## Anti-references

Avoid decorative animation, visual noise, ornamental terminal effects, unfamiliar interaction patterns, and status feedback that depends on motion. Do not trade information density or keyboard efficiency for presentation.

## Design Principles

1. Keep the user in flow: common actions remain immediate and keyboard-first.
2. Make state legible at a glance: hierarchy, selection, activity, and outcomes use consistent visual language.
3. Prefer stable feedback: update when meaningful state changes instead of animating continuously.
4. Preserve information density: use the terminal area efficiently without crowding essential labels.
5. Earn every visual treatment: color, symbols, and emphasis communicate function rather than decoration.

## Accessibility & Inclusion

Status must never depend on animation or color alone; retain distinct textual or symbolic indicators. Keep semantic colors configurable through themes, preserve readable contrast, and avoid unnecessary motion. All core workflows must remain fully keyboard accessible.
